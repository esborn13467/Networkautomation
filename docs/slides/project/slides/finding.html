Key finding

A model trained only on normal traffic cannot see what never changes in it

The problem

Failed logins and the off-hours flag are always zero in normal traffic, so the trees never split on them. Brute force and off-hours: 0% detected.

The fix

Train on unlabelled traffic in which attacks are rare, and add one rule for slow password guessing. Result: 100% detected, no extra false alarms.

This is the most important lesson from the project. Isolation Forest builds its trees only from features that vary in the training data. In normal traffic, failed logins and the off-hours flag are always zero, so the model was blind to them. Training on unlabelled traffic in which attacks are rare fixed this; the model still never sees a label. Slow password guessing changes only one feature, so one simple rule handles it, without extra false alarms.
